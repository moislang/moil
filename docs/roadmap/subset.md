# Compiler subset

This matrix separates implemented capability from compatibility with
`moisc`. A row only advances after compiler Mois source uses the feature and
a previous stage can compile it.

| Area | Current seed | Next gate |
|---|---|---|
| Compiler sources | camelCase `.snl` modules; project build; internal assembly of its own sources | Resolve imports and compile general projects directly in the Mois compiler |
| Frontend | Subset lexer/parser with stable `SNV1001` lexical and `SNV2001` parse diagnostics carrying byte spans; `SNV3001` identifies lowering failures by the failing statement's line and the function index; classes with fields, instance methods, positional constructors, `static` methods and skipped `@Annotation`s (ADR-0007) | Precise lowering spans, phase-specific messages, semantic diagnostics and a versioned differential against the reference |
| Semantics | Local resolution needed by the subset; static types of literals, locals, parameters and fields; `let`/`var` initializer annotations, local assignments and field assignments checked when both types are known (`SNV4001`–`SNV4003` on mismatch); call argument counts checked against the callee (`SNV4006`); argument types checked when both the parameter (or constructor field, or `push` element) type and the argument type are known (`SNV4007`); `T[]` annotations now keep a known element type; binary, logical and equality operators reject known incompatible operands, and `<`/`>`/`<=`/`>=` require `int` (`SNV4008`); unary `-`/`!` and a known non-`int` index are rejected (`SNV4009`); `if`/`while` conditions of a known non-`bool` type are rejected (`SNV4010`); assignment to `let` locals, parameters and `for`/`match` bindings rejected (`SNV4005`); `match` on a subject whose static type is a known enum must have a `_`/binding arm or cover every variant (`SNV4004`, the rule of moisc `sn_check_match_exhaustiveness`/`MOISL0205`, including a call subject whose return type is a known enum); declared function return types are tracked and a known mismatch is rejected (`SNV4011`); a `let`/`var` initializer that is a call of known return type is checked by `SNV4001`; use after moving an array or object local is rejected (`SNV5001`), and moving a movable value out of a field or array element is rejected (`SNV5002`); codes map to `moil check` codes in [diagnostics.md](diagnostics.md)); `==`/`!=` between known, different types is an error (`SNV4008`), not warning `SNW0001` | Complete type compatibility and diagnostics by milestones; full spans; address comparison `&T == &E` once references enter the subset |
| IR and backend | Lowering to SnBC; the transitional `moil build` binary is SnBC + bundled C VM; native backend in Mois (`native`): SnBC → aarch64 assembly, assembled by `as`/`ld`. N1 covers numeric operations; N2 covers strings, arrays, structs, printing, files, arguments and environment through the Mois runtime; N3 compiles the ordered compiler modules natively and reaches repeated assembly equality (`make bootstrap-native-self`); unit enum variants (`VARIANT` 42 without payload) and `match` (`IS_VARIANT` 43, literal, binding and wildcard arms, trap 52) run in the Mois executor and the native backend as tag 7 values | General imports and source-order independence; enum payloads, async/spawn, doubles and globals remain outside the native subset (doubles and globals are not lowered by the frontend either); N4 toolchain independence remains optional |
| Runtime | Mois facade for arguments, environment and I/O; SnBC validator; iterative SnBC executor in Mois that runs the compiler image; **native runtime in Mois** (`bootstrap/runtime/`, types `Primitive`, `System`, `Heap`, `Runtime`, `Text`, `Container`, `Ownership`, `Value`, `Host`): size-class heap with immediate release and `munmap`, ownership counts with static borrow elision, strong-cycle rejection, byte strings, arrays, objects, value equality, printing, files, arguments and environment; assembly only in the native `Primitive`/`System` stubs (ADR-0006) | Frontend borrow checker and weak references; faster copies for N3; the SnBC executor still uses the `/tmp` scratch file while it runs on the `moil` C VM (ADR-0004) |
| Library | `bootstrap/library/`: `BinarySearch`, `LinearSearch`, `Sorting`, `BinaryHeap`, `BinaryTree`, `IntMap` (SnBC and native, zero live blocks). `BinarySearch`, `LinearSearch` and `Sorting` have a stateless instance API, and `IntCell` and `IntArray` an instance API with positional constructors, that `moil build` v0.3.0 builds (`make bootstrap-library-root`) and are staged into the first-stage project; the other types still use static methods | Instance API for `BinaryHeap`, `BinaryTree` and `IntMap`; then a compiler module that uses the library (ADR-0007; slices in SPEC-0001, [snl#5](https://github.com/moislang/snl/pull/5)) |
| CLI | Input and output paths as arguments; internal bootstrap mode through `SNL_OUTPUT` | Flags, diagnostics and projects compatible with `moisc` |
| Self-compilation | The Mois seed compiles its source to SnBC; the Mois VM runs it to the same image; the native compiler repeats compilation to an identical assembly fixed point on the current host | Repeat the cycle after each extension and record hashes; clean-build reproducibility, Mach-O normalization and independent DDC remain separate gates |
| Full compatibility | Not demonstrated | `moisc` corpus with differential results and explicit gaps |

## Implementation rule

All new compiler, runtime and development tool code must be written in Mois.
C/C++ is not an alternative implementation. The installed `moil` seed is only
the transitional root used to obtain the first artifact; the chain advances
when the generated Mois compiler can compile its own revision and produce the
same artifact. Indispensable system calls stay behind small ABI contracts,
with no compiler logic outside Mois.

The compiler is the only product/publication piece of this project. Build
scripts and documentation are development support, not public toolchain
components.
